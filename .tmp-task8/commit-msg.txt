feat: ship .deb packages with systemd user unit on releases

cargo-dist has no native .deb installer, so add a custom post-announce job
that repacks the released Linux musl tarballs into Debian packages and
uploads intentd_<version>_{amd64,arm64}.deb onto the same GitHub release:

- packaging/deb/intentd.service: systemd *user* unit with the exact
  semantics `intentd service install` used to generate (Type=simple,
  ExecStart=intentd serve, ExecStop=intentd stop, Restart=on-failure,
  WantedBy=default.target), with the packaged /usr/bin/intentd path.
- packaging/deb/postinst: prints the `systemctl --user enable --now
  intentd` hint; deliberately does NOT auto-enable (maintainer scripts run
  as root and cannot enable user units per user).
- scripts/build-deb.sh: repacks a musl tarball into a .deb via dpkg-deb
  (binary at /usr/bin/intentd, unit at /usr/lib/systemd/user/).
- .github/workflows/build-deb.yml: reusable post-announce workflow
  (declared via post-announce-jobs in dist-workspace.toml, materialized
  into release.yml with `dist generate`); downloads both musl tarballs,
  builds and verifies the .debs, uploads them with `gh release upload`.
  Dry-runnable via workflow_dispatch (tag input, upload=false attaches
  workflow artifacts instead of touching the release).
- ci.yml: deb-packaging job asserting the unit content and building a
  stub .deb through scripts/build-deb.sh.
- README: Debian/Ubuntu install section.

Smoke-tested against the v0.1.1 release tarballs in a debian:bookworm
container: dpkg -i installs cleanly, postinst prints the hint, the unit
lands at /usr/lib/systemd/user/intentd.service, and /usr/bin/intentd
--version runs.
