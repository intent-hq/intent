# Initial Porting — Breadcrumbs

A living progress log for the **initial port of Intent's backend to a headless Rust daemon** (`intentd`). This is the durable trail future agents read first to understand where the port stands, and append to as work lands.

See also: [IMPLEMENTATION_SPEC.md](./IMPLEMENTATION_SPEC.md) (target architecture), [PROTOCOL.md](./PROTOCOL.md) (wire contract), and the root [AGENTS.md](../../AGENTS.md) (workflow + breadcrumb-update policy).

## Goal

Port Intent's backend to a standalone, headless Rust daemon (`intentd`) speaking **JSON-RPC 2.0 over a Unix-domain socket**, local-first. Scope of **this** effort is the **Rust backend only** — no frontend (Tauri/Svelte) yet. The Electron app in `augmentcode/intent` is the behavioral ancestor; the wire contract is defined in PROTOCOL.md.

### 2026-07-13 — `git.discard` — discard working-tree changes with reference parity (intentd PR #115 merged)

- **intentd PR #115 (squash → `main` @ `420382e6`):** ports `git.discard(workspaceId, paths)` — the last missing `git.*` catalog-parity write, mirroring the reference `gitService.discardChanges`. Tracked paths are restored from the index (equivalent to `git checkout -- <paths>`) via a batched libgit2 checkout with `SAFE | FORCE | UPDATE_INDEX` semantics and an explicit `paths` allowlist; untracked paths (files + directories) are deleted from disk best-effort — files are `fs::remove_file`d, directories walked via `fs::remove_dir_all`; staged changes are untouched (we operate on the working-tree delta only). Idempotent on already-clean tracked paths and on missing untracked paths (ENOENT swallowed for parity with the reference's race-tolerant `fs.unlink`). Classification is index-driven: a pathspec whose target is present in the index — as an exact-file entry OR as a directory whose contents are tracked — is routed through the checkout batch (this is what prevents `remove_dir_all` from wiping tracked content reachable via a bare `<dir>` pathspec, since libgit2's index probe is exact-file only); everything else falls through to the disk-delete branch. Path safety is enforced up-front: absolute paths outside the worktree, `..` traversal (both explicit components and lexical-normalization escapes like `a/../tracked.txt`), the empty and `.` worktree-root pathspecs, and `.` / `*` / `--all` are refused with `-32602` (unsafe path) or `-32603` (discard-all), depending on the class. The discard-all guard runs in a dedicated `parse_discard_paths` (not the shared stage parser) so `.` / `*` / `--all` are refused in every input shape — top-level string, CSV entry, and array element — closing the array-form bypass where `["*"]` / `["--all"]` would fall through the stage parser (which only inspected the top-level string) and devolve into a silent `ok: true` no-op. The error map is: workspace / worktree lookup failures surface as `-32603` (parity with `git.stage` / `git.unstage`); path safety violations from `intent_git::stage::discard` surface as `-32602` (unsafe pathspec); the tracked-batch checkout propagates as `Error::Git` — per-file untracked-deletion failures are logged and swallowed, matching the reference's warn-and-continue behavior. Ports the legacy `git:discard-changes` IPC. ### 2026-06-27 — Exclusive data-dir flock (single-instance backstop)
