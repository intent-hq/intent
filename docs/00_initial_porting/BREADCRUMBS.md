# Initial Porting — Breadcrumbs

A living progress log for the **initial port of Intent's backend to a headless Rust daemon** (`intentd`). This is the durable trail future agents read first to understand where the port stands, and append to as work lands.

See also: [IMPLEMENTATION_SPEC.md](./IMPLEMENTATION_SPEC.md) (target architecture), [PROTOCOL.md](./PROTOCOL.md) (wire contract), and the root [AGENTS.md](../../AGENTS.md) (workflow + breadcrumb-update policy).

## Goal

Port Intent's backend to a standalone, headless Rust daemon (`intentd`) speaking **JSON-RPC 2.0 over a Unix-domain socket**, local-first. Scope of **this** effort is the **Rust backend only** — no frontend (Tauri/Svelte) yet. The Electron app in `augmentcode/intent` is the behavioral ancestor; the wire contract is defined in PROTOCOL.md.

## Current submodule HEAD

- `packages/intentd` @ `90ba033` (**Milestone 6 (Iteration 3) — PTY host + workspace status model, STARTED**: **(a)** the new `intent-pty` crate — a unified `portable-pty` **host** (`PtyHost`) in which interactive terminals **and** scripts run as real PTYs in one host (so a terminal can attach to a running script), with bounded server-side scrollback (back-fill recent history then tail live), multi-client output fan-out, serialized stdin into the single PTY master, resize + SIGINT signal delivery, and session/workspace-scoped process-group reaping (the PTY child is a `setsid` leader so `killpg` reaps the whole tree — no orphans); engine-only, it exposes a clean API for the wire layers (`terminal.*`/`script.*`) and contains no wire methods/script policy/status model itself. **(b)** the **workspace activity/attention status model** (§9.9) — a derived `WorkspaceActivity` (`Idle`/`AgentRunning`, **never persisted**, computed from live agent state), server-owned persisted `attention` (`None`/`Unread`/`ReviewRequired`, reusing the existing column + the existing `workspace.markSeen`/`dismissAttention` RPCs), and self-sufficient **only-on-change** `workspace:activity-changed`/`attention-changed` events. Atop the **Milestone 5 — Cycle G COMPLETE** base: the §11.3 security review + hardening, the hermetic mock ACP harness (§13.2), the E2E transport + lifecycle suite (§13.1), and the Cycle F daemon (mDNS discovery, single-instance enforcement + idle reaping, CLI control + daemonization))

- **PTY host (Milestone 6 (Iteration 3) — T1, §12.1):** a new `intent-pty` crate (depends on `intent-core` only per §3.2) — a unified `portable-pty` **host** (`PtyHost`) in which interactive terminals **and** scripts run as real PTYs in one host, so a terminal can attach to a running script. Provides PTY spawn/resize/signal (SIGINT) over `portable-pty`; **bounded server-side scrollback** (`scrollback::Scrollback`, porting `script-output-buffer.ts`) so output survives client disconnects and a late-attaching subscriber **back-fills recent history then tails live**; **multi-client output fan-out** (broadcast, porting `MainProcessTerminalManager.ts`) with stdin from any client **serialized** into the single PTY master; and **session/workspace-scoped lifetime** — each PTY carries a scope key, `kill_scope` tears a scope down, and the PTY child is a `setsid` session leader so `killpg` reaps the whole tree (no orphaned grandchildren, reusing the M5 process-group pattern). Engine-only: exposes `PtyHost`/`SpawnSpec`/`Attachment`/`PtyId`/`PtySize`/`PtySignal` for the wire layers (`terminal.*` and `script.*`, deferred to later in Milestone 6) and contains **no** wire methods, script policy, or status model. - **Workspace activity/attention status model (Milestone 6 (Iteration 3) — T4, §9.9):** `Workspace` now carries a derived `activity` (`WorkspaceActivity::Idle`/`AgentRunning`) computed from live `AgentManager` state and **never persisted** — `workspace.list`/`workspace.get` fill it on read, and `AgentManager` increments/decrements a per-workspace running-agent count on agent start/teardown, emitting a `workspace:activity-changed` only when the derived value flips. The server-owned **`attention`** flag (`None`/`Unread`/`ReviewRequired`) stays **persisted** (reusing the existing column) and is raised/cleared BE-side (`raise_attention`) and via the existing `workspace.markSeen`/`workspace.dismissAttention` RPCs. Both surfaces emit **self-sufficient, only-on-change** events — `workspace:activity-changed { workspaceId, activity }` and `workspace:attention-changed { workspaceId, attention }` (§10.1). Touched `intent-services`, `intent-core`.
