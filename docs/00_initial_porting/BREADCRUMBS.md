# Initial Porting — Breadcrumbs

A living progress log for the **initial port of Intent's backend to a headless Rust daemon** (`intentd`). This is the durable trail future agents read first to understand where the port stands, and append to as work lands.

See also: [IMPLEMENTATION_SPEC.md](./IMPLEMENTATION_SPEC.md) (target architecture), [PROTOCOL.md](./PROTOCOL.md) (wire contract), and the root [AGENTS.md](../../AGENTS.md) (workflow + breadcrumb-update policy).

## Goal

Port Intent's backend to a standalone, headless Rust daemon (`intentd`) speaking **JSON-RPC 2.0 over a Unix-domain socket**, local-first. Scope of **this** effort is the **Rust backend only** — no frontend (Tauri/Svelte) yet. The Electron app in `augmentcode/intent` is the behavioral ancestor; the wire contract is defined in PROTOCOL.md.

## Implemented surface so far

- **JSON-RPC methods (78 request methods + 1 server-initiated notification):** full CRUD across four domains plus the event, local-git, PR, and code-review surface over UDS, backed by SQLite —
  - `workspace.*` (9): `list`, `get`, `create`, `update`, `archive`, `unarchive`, `delete`, `markSeen`, `dismissAttention`.
  - `note.*` (12): `list`, `get`, `create`, `update`, `setContent`, `add`, `edit`, `editLines`, `updateMetadata`, `listTasks`, `readAsset`, `delete`.
  - `task.*` (8): `markAsTask`, `update`, `updateStatus`, `updateNoteStatus`, `getMyTask`, `createPrerequisite`, `assignAgent`, `convertBlocks`.
  - `comment.*` (5): `add`, `list`, `getThread`, `respond`, `delete`.
  - `event.*` (7): `recentFiles`, `agentActivity`, `workspaceSummary`, `directoryChanges`, `query` (query/aggregation), plus the deprecated singular `subscribe`/`unsubscribe` aliases.
  - `events.*` (2 + notification): the `events.subscribe`/`events.unsubscribe` subscription fast-path and the server-initiated `events.event` push notification.
  - `git.*` (6): `status`, `stage`, `getBranches`, `commit`, `agentCommit`, `checkMergeConflicts`.
  - `pr.*` (12): 5 reads + 7 writes/actions, all **active-PR gated** (`-32603` when no active PR is linked).
  - `file-tracking.*` (8): `init`, `sync`, `load`, `getChanges`, `loadCommits`, `getLineStats`, `stage`, `unstage`.
  - `metrics.*` (4): `getWorkspaceStats`, `getAgentStats`, `getAllWorkspaceStats`, `clearAgentStats`.
  - `accept-changes.*` (5): `getStatus`, `prepare`, `execute`, `mergePR`, `addRemote`.
- **Events:** append-only `Event` domain + event-type taxonomy (`intent-core`); durable append-only event log via the `0003_events` migration + `event_repo` (`intent-store`); in-process `EventBus` + filter engine with `subscriber_count` observability (`intent-services`); bidirectional UDS transport that pushes `events.event` and serves the `events.subscribe`/`unsubscribe` fast-path (`intent-transport`); a notify-based file watcher emitting debounced `file:changed` events (`intent-services`); and the M1 workspace/note/task/comment CRUD mutations now emit change events onto the bus.
- **CLI:** `intentd serve`, `intentd call`, `intentd status`, `intentd doctor` (verifies migrations are applied incl. the `0004` agent_session gate + reports provider discovery — which providers are installed/authed), and `intentd mcp-bridge --connect <addr>` (the stdio↔TCP MCP proxy referenced from a generated `--mcp-config`).
- **Transport:** JSON-RPC 2.0 router over UDS (newline-delimited, mode `0600`, stale-socket cleanup, SIGINT/SIGTERM handling), error codes `-32700`/`-32600`/`-32601`/`-32602`/`-32603`, plus server-initiated `events.event` notifications. UDS listener + control client are `cfg`-gated so non-Unix targets (Windows) build cleanly.
- **Persistence:** SQLite via `sqlx` with embedded migrations (WAL, `foreign_keys`, `busy_timeout`), incl. the `0002_comments` and `0003_events` migrations.
- **Tests:** end-to-end UDS lifecycle + events integration tests plus camelCase wire-parity fixtures.
- **ACP foundation:** provider registry + model resolution (`intent-providers`); ACP client core — subprocess spawn, hand-rolled NDJSON JSON-RPC transport, reader/dispatch loop, `initialize` handshake, session lifecycle (`new`/`load`/`prompt`/`cancel`) with `session/update`→event-bus streaming, client-served filesystem read/write, permission-request flow, and a terminal stub (`intent-acp`); the `AgentSession` entity + `agent_repo` persistence via the `0004_agent_session` migration; and the `WorkspaceApi` trait (`intent-core`).
- **ACP orchestration (Cycle B):** the `AgentManager` multiplexer + process registry (global concurrency cap + LRU idle eviction) wired into `cmd_serve` (`intent-services`); the agent→BE **MCP callback server** (`WorkspaceMcpServer`) over the same `Arc<dyn WorkspaceApi>` the FE uses, universal MCP-config translators (`toAcpMcpServers`/`toAuggie…`/`toCodex…`/`toOpenCode…`), baseline-env injection + secret redaction, and the per-agent-type tool denylist (§18.4) (`intent-acp`); the **`agent.*` RPC surface** (24 methods); and the **live MCP spawn-wiring** — `AgentManager::create_agent` stands up a per-agent denylisted MCP server, serves it over a loopback **bridge** (`intent-acp::mcp_bridge`: a TCP NDJSON listener + the `intentd mcp-bridge` stdio↔TCP proxy), and writes the generated `--mcp-config` so a real spawned child reaches the in-process server. Proven by a hermetic spawned-child **E2E** (the `mock` provider's node agent performs a real `add_to_note` MCP `tools/call`; asserts BE state change + streamed chunks + exactly one `agent:stream:end` + persisted conversation).
- **Agent runtime wiring (M3.10):** the `agent.*` RPC handlers are now wired to the `AgentManager` **live runtime** rather than stubs (`intent-services`) — `agent.sendMessage` lazily spawns the child on the first turn (the TS spawn-on-first-message semantics), drives the ACP turn through `AgentManager::run_turn` in a background worker, and drains the in-memory send queue (flipping each queued message to in-flight when the current turn ends, the **queue-flip** loop); `agent.forceMessage` interrupts (aborts) the in-flight worker then delivers immediately; `agent.stop` aborts the in-flight turn worker, clears the busy flag, and drops the handle (killing the child via `kill_on_drop`) + deregisters. Proven over the wire by the new **over-the-wire E2E** `tests/uds_agent_runtime.rs`: it launches the real `intentd serve` daemon (mock provider) and drives `agent.create` + `agent.sendMessage` over UDS, asserting the daemon-spawned child reached the per-agent workspace MCP server via the generated `--mcp-config` (mutating the note) and that both the tool's `note:updated` domain event and the terminal `agent:stream:end` arrive over the transport.
- **GitHub / PR (Milestone 4 — Cycle B):** a new `intent-sourcecontrol` crate — the `SourceControl` trait + `GitHubSourceControl` over **octocrab** (REST + GraphQL), token resolution (keyring → env → `gh` CLI), GitHub Enterprise (GHE) base-URL support, a provider **registry**, and graceful `NotConfigured` behavior when no token/host is available. Backs the full **12-method `pr.*` surface** (5 reads + 7 writes/actions, active-PR gated with `-32603`) routed end-to-end (`intent-sourcecontrol` → `intent-services` `pr_ops` → `intent-transport`). Plus **PR↔workspace linking**: `head.ref` **branch-only** matching, the `0005_workspace_pr` migration persisting `prStatus` + `activePullRequest`, and a 60s background + on-demand refresh emitting `pr:linked`/`pr:updated`/`pr:unlinked` events. Touched `intent-core`, `intent-sourcecontrol`, `intent-services`, `intent-store`, `intent-transport`, `intentd`.
- **Local git (Milestone 4 — Cycle A):** a new `intent-git` crate (git2/libgit2, depends on `intent-core` only per §3.2) backing the six `git.*` JSON-RPC methods end-to-end (`intent-git` → `intent-services` `git_ops` → `intent-transport` router): `git.status` (file-level `GitStatus` with branch/ahead/behind/diverged + `files[]`), `git.stage` (CSV-string or array paths; staging all — `.`/`*`/`--all` — rejected with `-32603`), `git.getBranches` (`repoPath` + `includeRemote?`; unknown/unauthorized path → `-32602`, known-repo set derived from persisted workspaces), `git.commit` (deprecated; empty-commit guarded), `git.agentCommit` (`{ ok, hash, files, fileCount }`), and `git.checkMergeConflicts` (libgit2 in-memory `merge_base`+`merge_trees`; no base → `cannotDetermine`). Plus two internal helpers for Cycle C (no wire method yet): a lazy diff helper (additions/deletions + hunks via blob SHAs) and a worktree-create + per-path async lock (`WorktreeLocks`). Parity-exact result shapes/casing vs the TS `ws-git-api` ground truth; proven by a UDS write-ops round-trip test.
- **Code Changes Review (Milestone 4 — Cycle C):** the BE-internal change-tracking + attribution pipeline, metrics aggregation, and accept-changes orchestration — backed by the additive `0006_code_review` migration (the `tracked_changes` per-file audit trail with raw content kept lazy via git blob SHAs, never inlined) and the new `intent-store` repos (`tracked_changes_repo`, `diffs_repo`, `metrics_repo`). Adds **17 JSON-RPC methods** routed end-to-end (`intent-services` → `intent-transport`): `file-tracking.*` (8), `metrics.*` (4), and `accept-changes.*` (5). `accept-changes.execute` implements `commit` (cascading → `push` → `create-pr`), `push`, and `create-pr`, with `accept-changes.mergePR` performing the PR merge; the `ChangeStage` gains a `pull_request` stage with `pushed`→`pull_request`→`merged` transitions. The `intent-git` `WorktreeLocks` mutex is now wired on the services commit path (per-worktree `with_lock`). Emits the new `changes:metrics-changed` event (alongside `changes:tracked`/`changes:git-status`) after a mutating step. Touched `intent-core`, `intent-git`, `intent-services`, `intent-store`, `intent-transport`, `intentd`.

## Deferred / planned (NOT yet built)

- The remaining PROTOCOL methods (106 total in the contract).
- TCP / TLS / WSS transports, mDNS discovery, bearer-token auth.
- Context engine, PTY, search.
- **Local git (Milestone 4 — Cycle A) accepted deferrals:** the `autoCommit` gate → a future **settings store** (`assertAgentCommitAllowed` ported with the TS default `true` + `userRequested` bypass; seam preserved); `Agent-Id`/`Linked-Note-Id` commit trailers (no agent context at the UDS layer yet); libgit2 has no pre-commit hooks and no `git merge-tree` (in-memory tree merge used instead); and `getBranches` known-repo set derived from persisted workspaces rather than a repo registry.
- **GitHub / PR (Milestone 4 — Cycle B) accepted deferrals:** PR↔workspace matching is **branch-only** (`head.ref`) vs the TS branch-OR-`baseRef` match; `pr:*` wire events are an **intentd extension** (not in the original TS contract); **capability gating + pagination** deferred (single-page reads); `pr.listComments` returns a **host-agnostic** comment shape; timestamps are **RFC-3339**.
- **Code Changes Review (Milestone 4 — Cycle C) accepted deferrals:** the `accept-changes.execute` actions `merge` / `export` / `undo-push` / `undo-commit` / `reset-to-trunk` / `rebase-onto-trunk` return `not supported by intentd yet` — they depend on libgit2 merge/rebase/fetch + remote RPC not yet ported (PR-merge is available via `accept-changes.mergePR`).
- A real **auggie** end-to-end turn in CI: best-effort/local only (requires auggie + login). The hermetic mock-agent E2E is the CI gate; the generated `--mcp-config` + bridge are auggie-consumable.
- `agent.stop` parity follow-ups deferred to **Milestone 5**: (1) the keep-alive stop variant via `provider.interrupt` (the current stop kills the child via `kill_on_drop` rather than interrupting and keeping the session warm); and (2) `agent.stop` emits **no** terminal `agent:stream:end` event.
- Transport panic-safety via `catch_unwind` → `-32603` (currently relies on per-connection `tokio::spawn` isolation).
- Event surface follow-ups deferred (verified parity-safe): `task:ready-tasks-changed` emission, saga-driven `workspace:*` events, and the `Event.metadata` field.
- `file:*` distinct-type modelling deferred to Milestone 8 (the watcher currently emits `file:changed`).
- The entire frontend (Tauri/Svelte).
