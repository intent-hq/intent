# Initial Porting — Breadcrumbs

A living progress log for the **initial port of Intent's backend to a headless Rust daemon** (`intentd`). This is the durable trail future agents read first to understand where the port stands, and append to as work lands.

See also: [IMPLEMENTATION_SPEC.md](./IMPLEMENTATION_SPEC.md) (target architecture), [PROTOCOL.md](./PROTOCOL.md) (wire contract), and the root [AGENTS.md](../../AGENTS.md) (workflow + breadcrumb-update policy).

## Goal

Port Intent's backend to a standalone, headless Rust daemon (`intentd`) speaking **JSON-RPC 2.0 over a Unix-domain socket**, local-first. Scope of **this** effort is the **Rust backend only** — no frontend (Tauri/Svelte) yet. The Electron app in `augmentcode/intent` is the behavioral ancestor; the wire contract is defined in PROTOCOL.md.

Atop the **Track C — `chat.subscribe` live transcript channel** — an **agent-scoped** live chat channel built on the TB-0 snapshot+delta engine, the canonical structured alternative to the `agent:stream:*` firehose (PROTOCOL §7.1). `chat.subscribe`/`chat.unsubscribe` (per-agent, `{ agentId }`; missing/empty `agentId` → `-32602`) join the subscription fast-path: each returns `{ subscriptionId }`, then a **seq-0 messages snapshot** (the newest `agent.getConversation` page, reused verbatim, **plus** a synthetic in-flight `assistant` message — `isStreaming: true` — reconstructed from the live turn when one is streaming, so a mid-turn (re)subscriber renders a coherent partial), then ordered **block-level** `{ added, updated, removedIds }` deltas built straight from the enriched `agent:stream:chunk`/`agent:tool:call` payloads (in-flight content is unpersisted until `stream:end`, so the channel cannot use the re-read strategy). Every assistant block carries a stable `{messageId}:{blockIndex}` id (the assistant UUIDv7 minted at **turn start** + the coalesced block index), so deltas patch the snapshot exactly; `added` = a block's first appearance, `updated` = a grown/changed block carrying the **full** block (idempotent replace), and `removedIds` is **non-empty for orphan self-heal** (a trailing partial the durable turn dropped, or a mispredicted `tool_result` index). The channel tails `agent:tool:call` and synthesizes TS-shaped `tool_use` + `tool_result` blocks. On `agent:stream:end` it reconciles against the now-persisted message (every block as `updated`/`added` with the authoritative `messageSeq`/`timestamp`/`streamingComplete:true`, plus `removedIds`), guaranteeing the **invariant**: the seq-0 snapshot reduced with every delta (honoring `removedIds`) equals a fresh `agent.getConversation` snapshot. Additive — **coexists** with the unchanged `events.subscribe` firehose. Proven by `uds_chat_subscription.rs` (8 tests: snapshot+delta mapping, tool-block synthesis, mid-turn resume, per-agent isolation, firehose coexistence, and `chat_delta_orphaned_block_reconciles_via_nonempty_removed_ids` — the only test that drives a non-empty `removedIds`). ### 2026-06-27 — Track C: `chat.subscribe` live transcript channel

Landed the agent-scoped live chat channel on the TB-0 snapshot+delta engine — the canonical structured alternative to the `agent:stream:*` firehose (PROTOCOL §7.1). `chat.subscribe`/`chat.unsubscribe` (per-agent, `{ agentId }`, missing/empty → `-32602`) join the subscription fast-path: each returns `{ subscriptionId }`, then a **seq-0 messages snapshot** (the newest `agent.getConversation` page reused verbatim, plus a synthetic `isStreaming:true` assistant message reconstructed from the live turn so a mid-turn (re)subscriber renders a coherent partial), then ordered **block-level** `{ added, updated, removedIds }` deltas built straight from the enriched `agent:stream:chunk`/`agent:tool:call` payloads (in-flight content is unpersisted until `stream:end`, so the channel cannot use the re-read strategy). Proven by `uds_chat_subscription.rs` (8 tests: snapshot+delta mapping, tool-block synthesis, mid-turn resume, per-agent isolation, firehose coexistence, and `chat_delta_orphaned_block_reconciles_via_nonempty_removed_ids` — the only test driving a non-empty `removedIds`); `make check` + `make test` green.
